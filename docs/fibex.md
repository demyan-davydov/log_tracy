# FIBEX: декодирование non-verbose DLT

Статус: **решение принято 2026-11-14**: FIBEX у документа (вариант 2); работа в `docs/stories/fibex.md`. Ниже — что было известно на 2026-11-04 и какие были варианты.

## Что это и зачем

DLT-сообщение бывает двух видов:

- **verbose** несет все в себе: тип каждого аргумента, длину строки, саму строку. Читается без внешних файлов (так пишут, например, Linux-приложения через демон DLT);
- **non-verbose** — экономный режим слабых ECU (обычно классический AUTOSAR): передаются только 4-байтный **Message ID** и сырые байты значений, без типов и без текста. Сейчас такое сообщение показывается как `[11] 2A00 |*.`.

**FIBEX** (ASAM Field Bus Exchange Format, XML) генерируется при сборке прошивки и хранит выброшенное: для каждого Message ID — AppId/CtxId, тип и уровень, исходный файл и строку, и последовательность частей сообщения (статический текст `DESC` или значение типа `UINT16`, `SINT32`, `FLOAT`, строка…, иногда с именем и единицей). С ним `[11] 2A00` показывается как `APP1 CON1 warn  Buffer near limit. Free size: 42`.

FIBEX привязан к **версии прошивки**: после пересборки ID могут значить другое. К логу нужен FIBEX той же сборки, обычно по файлу (или папке) на ECU.

Масштаб: в `test_data/Trace_bPR_206_…_CU7_DLT_BRR.dlt` 162 589 non-verbose сообщений из 317 781 (ECU `VUC` — 144 278, `NAD` — 15 956, `IMX` — 2 355), 18 504 различных Message ID.

## Как это обычно сделано в просмотрщиках DLT


- **Подключение**: один путь — файл FIBEX или папка (загружаются все `*.xml`). Задается в настройках, перетаскиванием XML на окно или из командной строки. Путь хранится в **проекте** просмотрщика и действует на все открытое; к логу не привязан.
- **Поиск**: по Message ID; если у сообщения есть AppId/CtxId — по тройке (ID, AppId, CtxId). ECU в ключ не входит: в логе нескольких ECU с пересекающимися ID возможна путаница.
- **Подстановка**: AppId/CtxId (если их нет в сообщении), тип и уровень, payload из частей по порядку (`DESC` — текст, сигнал — значение по `CODING`); дальше сообщение показывается как verbose.
- Разбирается подмножество FIBEX, которое генерируют DLT-инструменты: вендорские поля `MANUFACTURER-EXTENSION` (`MESSAGE_TYPE`, `MESSAGE_INFO`, `APPLICATION_ID`, `CONTEXT_ID`, `MESSAGE_SOURCE_FILE`, `MESSAGE_LINE_NUMBER`), `FRAME` → `PDU-INSTANCE` → `PDU` → `SIGNAL-INSTANCE` → `SIGNAL` → `CODING`.

## Другие инструменты

По общим сведениям, не проверено: коммерческие инструменты для шин автомобиля держат файлы описаний, как и базы DBC для CAN, в **конфигурации проекта** с привязкой к каналу или ECU. В новых версиях AUTOSAR описание non-verbose сообщений может приходить в **ARXML** вместо FIBEX.

## Почему решение отложено

Везде база описаний живет отдельно от лога и подключается на уровне **проекта**. У нас проекта нет: открываются независимые файлы, у каждого свой формат и свои настройки в списке недавних. Ни один из вариантов ниже не ложится на эту модель без компромисса.

Техническое ограничение, которое надо учесть при любом варианте: FIBEX меняет не только текст, но и **AppId, CtxId, тип и уровень**, а по ним работают фильтры (правила по колонкам, `.dlf`) и поиск. Значит, FIBEX должен быть известен формату документа (экземпляр формата неизменяем и создается на документ), а его смена требует пересоздать формат и пересчитать индексы фильтра и поиска, а не только перерисовать строки. Индекс смещений остается: границы записей от FIBEX не зависят.

## Рассмотренные варианты

1. **Общий список в настройках** (файлы и папки); добавление из меню и перетаскиванием XML. Просто, но один набор на все открытые логи: логи разных прошивок или машин рядом дадут неверное декодирование.
2. **FIBEX у документа**: «Загрузить FIBEX…» для открытого файла, запоминается в записи списка недавних (как формат). Точно, но FIBEX нужно подключать к каждому логу.
3. **Автоматически рядом с файлом**: искать `.xml` в папке лога. Без UI, но работает только при таком соглашении о раскладке файлов.
4. **Ввести понятие проекта** (набор логов и описаний к ним). Самое общее, но это отдельное большое решение о модели приложения, затрагивающее не только DLT (DBC для CAN в том же положении).

Возможны сочетания, например 1 как набор по умолчанию и 2 как замена для документа.

## Открытые вопросы

- Входит ли **ECU** в ключ поиска (ID, AppId, CtxId, ECU), если ECU указан в FIBEX. Для логов нескольких ECU (как файл выше) это важно.
- Несколько FIBEX разных версий одной прошивки: как выбирать.
- Поддерживать ли **ARXML**.
- Что делать при изменении файла FIBEX на диске (перечитывать, переиндексировать).
