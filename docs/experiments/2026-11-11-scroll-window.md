# Прыжки по таблице лога: куда уходит время (2026-11-11)

## Вопрос

Почему перетаскивание бегунка полосы прокрутки, PageDown и End в большом логе тормозят, хотя
колесо прокручивает быстро, и что из этого можно убрать.

## Условия

- Apple M1 Pro, macOS, Sciter 6.0.5.5, debug-сборка (время почти целиком в Sciter, сборка
  приложения на него не влияет).
- Логи: сгенерированный DLT 512 МБ (`gen-log --size 512M`, 4 471 342 записи); запись RichOS
  15 ГБ (84 858 354 записи); `Case2.dlt` 45 МБ с фильтрами пользователя.
- Таблица ~484 px высотой, ~20–25 строк на экране, если не сказано иное.
- Время прыжка: `vlist.navigateTo(n)` и чтение геометрии последней строки (раскладка
  выполнена) через отладочный канал (`scripts/app.mjs`); профиль: `sample` во время серии
  прыжков.

## Результаты

Из чего состоит прыжок при окне Sciter по умолчанию (160 строк):

| Часть | Время |
|---|---|
| 160 строк от бэкенда (`itemAt`) | ~1 мс |
| JSX строк (`renderItem`) | ~4 мс |
| Весь прыжок | ~150 мс |

Профиль `navigate_to`: ширины колонок таблицы (`calc_intrinsic_widths`, из них подбор стилей
новых элементов ~32 %) — ~53 %; `prepare_scroll_down` — ~25 %; наш JS (`contentrequired`) — ~6 %.
Sciter сначала дорисовывает ~половину окна у старого места, потом целое окно у нового.

Не помогает (в пределах ±5 %): отключить перенос Payload, убрать `:before` якоря с transition,
сделать строки блочными вместо табличных.

Время прыжка линейно по размеру окна, ~0,95 мс на строку:

| `slidingWindowSize` | Прыжок |
|---|---|
| 160 | ~150 мс |
| 80 | ~75 мс |
| 50 | ~48 мс |
| 30 | ~28 мс |

Замена текста в уже отрисованных ячейках вместо новых строк: ~16 мс на 50 строк против ~50 мс
(стили не подбираются заново) — следующий возможный шаг, свой пул строк вместо `virtual-list`.

`navigateTo("end")` просит строку на пиксель высоты списка (483 строки при 483 px) при любом
окне: ~240 мс, на высоком окне ~0,5 с. Переход на номер последней строки — та же картина за
~38 мс (лог 15 ГБ).

## Вывод

Окно строк по высоте таблицы (`windowSize`): прыжок ~35–45 мс вместо ~150 мс, End ~38 мс вместо
~240 мс. Окно меньше строк на экране роняет Sciter, а заполняет он список половиной окна, —
отсюда запас (история: `docs/stories/scroll-window.md`).
