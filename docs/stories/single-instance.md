# Одна копия приложения

## Что

Релизная сборка запускается в одной копии на `settings.json`. Вторая копия, запущенная рядом
с первой, выводит строку в stdout, выводит окно первой копии на передний план и выходит.
Отладочная сборка (и `dub test`) запускается сколько угодно раз.

## Почему так

- Две копии с общим `settings.json` перезаписывают настройки друг друга: при выходе каждая
  пишет своё состояние окна, открытые файлы и фильтры, и побеждает та, что закрылась последней.
- Для отладки несколько копий полезны, поэтому ограничение только в релизе (`debug {} else` в
  `app.d`).
- Охраняется именно файл настроек, а не программа вообще: замок — `settings.lock` рядом с
  `settings.json`. Копия из другой папки со своими настройками ничему не мешает и запускается.
- Замок — блокировка открытого файла (`flock`, `LockFileEx`), а не сам факт существования
  файла: система снимает её, когда процесс завершается, даже аварийно, и оставшийся файл
  ничего не блокирует.
- Активация — как принято на системе:
  - macOS: `NSRunningApplication activateWithOptions:` по pid первой копии. Запуск .app из
    Finder и так не создаёт вторую копию (LaunchServices), замок нужен для запуска бинарника
    напрямую и из терминала. С macOS 14 активация чужого приложения кооперативная, система может
    её не выполнить: тогда вторая копия просто выходит.
  - Windows: видимое окно верхнего уровня без владельца и не tool window из процесса первой копии,
    `ShowWindow(SW_RESTORE)` для свёрнутого и `SetForegroundWindow` (только что запущенному
    пользователем процессу это разрешено).
  - Linux: ничего, только выход: способ зависит от X11/Wayland и композитора.
- Если файл замка не открылся (папка только для чтения) или не запирается (файловая система
  без блокировок), приложение запускается как раньше: «занято» — только ошибка чужого замка
  (`EWOULDBLOCK`, `ERROR_LOCK_VIOLATION`), иначе вторая копия не запустилась бы никогда.
- Первая копия пишет pid сразу после замка; вторая, прочитав пустой файл, ждёт его до 0,2 с.

## Как устроено

- `utils/single_instance.SingleInstance`: открывает файл, пробует взять замок; первая копия
  пишет в файл свой pid, вторая его читает (`firstPid`) и по нему активирует (`activateFirst`).
  На Windows замок стоит на байте за 1 МБ, далеко за pid: запертый диапазон другой дескриптор
  не прочёл бы.
- Путь замка — `ui/app_settings.instanceLockPath`.
- Проверяется в `app.d` до запуска Sciter.
