# Порядок в сборке

Ветка: `build`.

Сборка держалась на нескольких разрозненных скриптах: bundle-скрипт на каждую ОС (sh и bat),
проверка компиляции под Windows, тесты под Windows, плюс ручные шаги (положить библиотеку
Sciter рядом с программой и тестами, подписать ее на маке). Программа собиралась в корень
проекта, debug и release перетирали друг друга, бандлы тоже ложились в корень. Bundle-скрипты
вызывали `dub` без `--compiler=ldc2`. Библиотеки Sciter лежали в `libs/` вне git.

## Решение

- Библиотеки Sciter (`libs/`, 134 МБ на все платформы) хранятся в git через LFS:
  `.gitattributes` отдает LFS файлы `.dylib`, `.so`, `.dll` в `libs/`. Версия Sciter записана
  в `libs/SCITER_VERSION`: биндинг `source/sciter/capi` привязан к API конкретной версии.
- `dub.selections.json` теперь в git: для программы версии зависимостей фиксируются, чтобы
  сборка повторялась.
- Раскладку сборок делает сам dub (`dub.sdl`): `targetPath "build/$PLATFORM-$ARCH-$BUILD_TYPE"`
  кладет каждую сборку в свою папку (`osx-aarch64-debug`, `linux-x86_64-release`,
  `osx-aarch64-unittest` для `dub test`), а `copyFiles` по платформе и архитектуре кладет рядом
  библиотеку Sciter. Поэтому и голые `dub build` / `dub test` работают без ручного копирования
  (в свежем worktree тоже), а у каждой сборки свой `settings.json`.
- Один скрипт на Node (`scripts/build.mjs`) вместо bundle-скриптов на sh и bat, проверки
  компиляции под Windows и тестов под Windows: Node уже нужен проекту (`node --test`,
  `i18n-extract.mjs`), и один скрипт работает одинаково на всех ОС. Команды:
  - `build` (по умолчанию): debug под архитектуру машины, `--release`, `--arch x64|arm64`.
    Параметр — архитектура, а не платформа: собрать программу для другой ОС нельзя (для Windows
    с мака нет линковки).
  - `test`: D-юниттесты (`dub test`) и JS-тесты (`node --test tests/js`) вместе.
  - `dist`: релизный дистрибутив в `build/dist/<macos|linux|windows>/`.
  - `check-windows`: компиляция приложения и юниттестов под Windows x64 без линковки (бывший
    `check-windows-compile.sh`).
  - Чистая часть (разбор команды, аргументы dub, `Info.plist`, desktop entry) проверяется
    `tests/js/build-script.test.mjs`.
- `--help` (`-h`) у обоих скриптов печатает команды и параметры. Текст справки один, в
  `build.mjs` (`buildUsage`, `runUsage`), комментарий в начале скрипта ссылается на него; тест
  проверяет, что в справке есть каждая команда и параметр.
- `scripts/run.mjs` собирает так же (те же `--release`, `--arch`; `parseCommand` и `build`
  из `build.mjs`) и запускает программу из папки сборки, ее вывод — в тот же терминал.
  Отдельным скриптом, а не командой `build.mjs`: тот только собирает.
- `dist` собирает под одну архитектуру (машины или `--arch`), на маке пока только arm64.
  Universal binary (две сборки, склеенные `lipo`) отложен: для x86_64 линкеру нужен runtime
  ldc2 под x86_64, а в ldc из Homebrew его нет (только arm64). См. `docs/backlog.md`.
- Скрипт проверяет перед сборкой и тестами, что библиотека Sciter — не указатель LFS (свежий
  клон без `git lfs pull`): иначе все собирается, а программа падает на загрузке Sciter.
- `check-windows` спрашивает у dub аргументы компилятора для triple `x86_64-windows-msvc`
  одним вызовом (`--data-0`): dub считает платформу Windows, и то, что `dub.sdl` объявляет
  только для Windows, попадает в проверку.
- `dist` собирает дистрибутив во временной папке, копирует рядом с местом и переименовывает
  в `build/dist/<система>`: неудача на любом шаге оставляет прежний дистрибутив.
- Версия программы — файл `VERSION` в корне, `dist` подставляет ее в `Info.plist`.
- Подпись на маке: рядом с бандлом лежит `sign.command` (открывается из Finder в Терминале):
  снимает карантин и подписывает ad-hoc `libsciter.dylib`, потом бандл. `dist` подписывает им же.
  - Бандл собирается и подписывается во временной папке и копируется в `build/dist` через
    `ditto`: папка проекта в `Documents` синхронизируется iCloud, File Provider вешает
    `com.apple.FinderInfo` на новый `.app`, и codesign отказывается его подписывать
    («resource fork, Finder information, or similar detritus not allowed»). Подписанному
    бандлу этот атрибут уже не мешает.

- Описание сборки для людей — `docs/building.md`, с установкой окружения на каждой системе
  (Linux и Windows — по документации инструментов, не проверено). Только на английском: две
  версии разошлись бы, а для инструкции по установке расхождение хуже чужого языка. Раздел
  Commands в `CLAUDE.md` переписан под скрипт.

- CI — GitHub Actions (`.github/workflows/build.yml`), заранее, хотя remote еще нет: матрица
  трех систем, `test` и `dist` на каждой, `check-windows` на Linux, дистрибутивы — артефакты.
  Каждая система берет из LFS только свою библиотеку Sciter и кеширует ее (`actions/cache` по
  ее объекту LFS), чтобы не тратить трафик LFS на каждый запуск. Дистрибутив упакован в tar:
  артефакт GitHub — zip без прав на запуск. Запуск на push в любую ветку, без
  `pull_request`: ветки сливаются локально. Не запускался ни разу: что проверить — в
  `docs/backlog.md`.

- `--brief` (`scripts/build-output-filter.mjs`, 2026-11-10): весь вывод шагов — в `build/brief.log`,
  в терминал — только ошибки компиляции и линковки, упавшие тесты D и JS с местом и итог.
  Зеленый `test` давал 616 строк (~43 КБ) на каждый прогон агента, с `--brief` — одну.
  Отдельной утилиты-парсера не стали делать: формат вывода свой и стабильный, фильтр — часть
  скрипта сборки. stdout и stderr шага пишутся в один файл: так их строки не перемешиваются
  внутри строки, как было в терминале (`S62 modules passed unittests`). Шаг, ни одна строка
  которого не узнана, показывает свои последние строки, чтобы падение не прошло молча.

- Библиотеки Sciter в LFS — архивы brotli (`<library>.br`, 2026-11-14): 130 МБ на пять
  библиотек сжимаются до ~36 МБ. Объекты LFS не удаляются, пока жив репозиторий, и каждое
  обновление Sciter добавляло бы 130 МБ к хранилищу и столько же к трафику свежих сборок и CI.
  brotli, а не zip или xz: встроен в `zlib` любой версии Node, без пакетов; zip (deflate) сжимает
  как gzip (~48 МБ), и Node не читает zip без разбора заголовков; xz сжимает на 4 МБ лучше, но в
  Node его нет. Скрипт распаковывает архив рядом (библиотека — в `.gitignore`) и запоминает в
  `<library>.unpacked` хеш архива и размер и время библиотеки: распаковывает заново после checkout
  другого архива; если же поменялась библиотека, а архив нет (новый Sciter, еще не упакованный),
  сборка останавливается, а не затирает ее старой. Упаковка — `build.mjs pack-libs`, раз в
  обновление Sciter (2 минуты). Старые объекты LFS оставлены: переписывать историю ради них не
  стали.
