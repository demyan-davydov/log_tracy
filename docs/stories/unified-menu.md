# Единое главное меню

Ветка: `unified-menu`.

Сейчас главное меню есть только на macOS: `ui/main_menu_loader` строит нативное меню из
`resources/menu.json`. На Windows и Linux меню нет вовсе: в `main.htm` лежит скрытое демо-меню
из примеров Sciter, скрипт его не трогает. Хочется, чтобы меню описывалось в одном месте —
в приложении, — а каждая платформа получала его в своем виде.

## Требования

1. Меню описывается в D, в модуле без Sciter (`ui/app_menu`), и покрыто тестами.
2. Команды одни и те же на всех платформах (`file.open`, `app.settings`, `app.quit`, ...):
   скрипт получает их в `onMenuCommand(id)` откуда бы ни пришел клик.
3. Раскладка пунктов следует обычаям платформы:
   - macOS: меню приложения (Settings… ⌘,, Quit ⌘Q), File (Open File… ⌘O), Window
     (Minimize ⌘M);
   - Windows: File — Open File… Ctrl+O, Settings… Ctrl+,, Exit Alt+F4; меню Window нет;
   - Linux: как Windows, но выход называется Quit, Ctrl+Q.
4. Сочетания клавиш описываются один раз, без привязки к платформе (основной модификатор —
   Cmd на macOS, Ctrl на остальных), а их текст строится для платформы: `⇧⌘S` / `Ctrl+Shift+S`.
5. macOS: нативное меню строится из этого описания, `menu.json` больше не нужен.
6. Windows/Linux: меню-бар Sciter (`<ul id="menu-bar">` с `behavior: menu-bar`). Приложение
   отдает скрипту только модель меню в JSON (что за пункты), а рисует ее скрипт: D не знает,
   как Sciter строит меню.

## Первый шаг (проба)

На macOS строится нативное меню из нового описания, а разметка меню для Windows и Linux
печатается в stdout при запуске, чтобы ее можно было посмотреть. В окно на Windows/Linux она
пока не вставляется.

Сначала разметку меню-бара строил D (`menuBarHtml`). На втором шаге от этого отказались:
это лишняя связь D со Sciter, D теперь отдает модель (`menuJson`), а разметку строит скрипт.

## Второй шаг: меню в окне на Windows/Linux

1. Скрипт берет у бэкенда меню (`backend.menuBar()`, xcall `getMenuBar`) — модель в JSON
   уже для своей платформы: подменю, команды, разделители, у сочетания готовый текст
   (`Ctrl+O`) и `KeyboardEvent.code` с модификаторами. `null`, если меню-бара нет (macOS:
   там нативное меню). Решает бэкенд, а не скрипт; имя ОС скрипту не нужно.
2. Меню-бар рисует `resources/menu-bar.js` вместо демо-меню из примеров Sciter (оно удалено
   из `main.htm`). Клик по пункту вызывает `onMenuCommand(command)`.
3. Сочетания клавиш: `span.accesskey` только показывает текст, нажатия ловит скрипт.
   Список сочетаний из модели и сопоставление нажатия с командой — модуль без Sciter
   (`resources/menu-shortcuts.js`), с тестами. Сочетание, которое обрабатывает сама ОС
   (Alt+F4 на Windows, `bySystem`), только показывается.
4. `app.quit` на Windows/Linux закрывает окно (как крестик: состояние сохраняется).
5. Прежний обработчик Cmd/Ctrl+O в `script.js` больше не нужен: на macOS ⌘O — нативное меню,
   на остальных — список сочетаний. Он же открывал файл и по Cmd+F, это была ошибка.
6. Для проверки на macOS меню-бар включается переменной окружения
   `MENU_BAR_PLATFORM=windows` (или `linux`): бэкенд отдает меню этой платформы рядом с нативным.

## Третий шаг: мнемоники, подсказка, вид

1. Мнемоники Windows/Linux: в метке пункта `&` перед буквой (`&File`, `E&xit`), как в
   Windows; D разбирает ее один раз, при создании пункта (`parseLabel`). Модель отдает метку
   без `&` и номер буквы (`mnemonic`). Мнемоники обрабатывает скрипт, а не `accesskey` Sciter
   (проверено: ни Alt+F, ни буква в открытом меню через `accesskey` не работают): Alt+буква
   открывает пункт меню-бара, буква в открытом меню выбирает пункт. Как в Windows, буквы
   подчеркнуты только после нажатия Alt (до клика мышью). На macOS мнемоник нет.
2. Подсказка пустого окна «Open a log with ⌘O» берет текст сочетания `file.open` из модели
   меню (`Ctrl+O` на Windows/Linux), а не пишет `⌘O` сама. Для этого бэкенд отдает модель
   меню всегда, с флагом, рисовать ли меню-бар: `{menuBar, menus}`.
3. Цвета меню-бара и выпадающих меню — из переменных тем (светлая и темная), а не системные
   цвета примера Sciter.

## Четвертый шаг: кнопка вместо меню-бара (ветка `main-menu`)

Отменяет меню-бар и мнемоники второго и третьего шагов.

1. Почему. На Linux (Ubuntu, GNOME) меню-бар под заголовком окна GTK выглядел чужим и занимал
   целую строку: в GNOME у приложений меню-бара нет, есть кнопка главного меню в шапке.
   Посмотрев на вариант для Linux, владелец решил сделать так же и на Windows, вопреки ее
   соглашениям: одинаково и красиво важнее (`ux.md`, правило 25).
2. Что теперь. На Windows и Linux меню — один плоский список за круглой кнопкой ☰ справа от
   вкладок (`resources/main-menu.js`, бывший `menu-bar.js`). Список описан в `appMenu`, у двух
   платформ общий, отличается только выход: Exit Alt+F4 на Windows, Quit Ctrl+Q на Linux.
   macOS не изменилась: нативное меню с подменю.
3. Мнемоники убраны везде: в плоском списке буквы совпадали (S у «Show Bottom Panel» и
   «Settings», Н и П в русском переводе), а в главном меню GNOME их и нет. Вместе с ними ушли
   `parseLabel`, разбор `&` в псевдопереводе и проверка мнемоник в `i18n-extract.mjs`;
   ключи перевода стали без `&`.
4. Клавиши, открывающей меню, нет. F10 в GNOME открывает главное меню, но на Windows это
   системная клавиша (режим меню окна): перехватывать ее пришлось бы в D, а одна только для
   Linux снова развела бы платформы. У всех команд меню есть свои сочетания.
5. Вид всех меню, которые рисует Sciter (и контекстных, и открытых списков `<select>`), на всех
   платформах — как в GNOME: пункты выше, серая скругленная подсветка с отступом от краев,
   скругленные углы. Отступы, радиусы и цвета пробные.
6. Стили платформы — по медиапеременной `ui-platform`, которую скрипт ставит из
   `backend.menu().platform`, а не по встроенной `platform` Sciter: та на macOS всегда `OSX`, и
   вид Windows/Linux было бы не посмотреть. Переменная окружения `MENU_BAR_PLATFORM` стала
   `UI_PLATFORM`: меняет вид, но не ОС (Cmd/Ctrl, нативное меню macOS остаются).
7. Рассматривали и отклонили: свою шапку окна вместо заголовка системы (`window-frame`
   Sciter): экономит еще строку, но кнопки окна, перетаскивание, X11/Wayland пришлось бы делать
   самим, а Sciter 6.0.5.5 на Linux и так ломает модальные диалоги. Подгрузку разметки по
   платформе через `<include media>`: разница в разметке — одна кнопка, а состав меню все
   равно приходит из D.
