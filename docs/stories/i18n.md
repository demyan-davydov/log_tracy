# Интернационализация

Ветка: `i18n`.

Все, что пользователь видит в интерфейсе, должно переводиться. Сначала английский (исходный)
и русский. Содержимое логов, заголовки колонок форматов, уровни (Fatal, Error, Warn, ...) и
текст сочетаний клавиш не переводятся.

## Решения

1. **Подход как в Qt / gettext**: в коде пишется английский текст, он же ключ перевода и
   запасной вариант, если перевода нет:
   - `tr("Open File...")`, с параметрами `tr("Found {count}", { count })`;
   - контекст для омонимов: `trc("noun", "Filter")`;
   - множественное число: `trn("{n} match", "{n} matches", n)`.

   Аргумент — всегда строковый литерал: иначе строку не найти автоматически.
2. **Встроенный механизм Sciter (`@"text"`, хуки `JSX_translateText`) не используем**: это
   нестандартный синтаксис, модули с ним не загрузятся в `node --test`.
3. **Каталоги — JSON** (без своих парсеров и зависимостей), по файлу на язык:
   `resources/i18n/translations/<тег>.json`. Код слоя переводов лежит в `resources/i18n/`.

   ```json
   {
     "locale": "ru",
     "name": "Русский",
     "messages": {
       "&Open File...": "&Открыть файл...",
       "Filter|noun": "Фильтр",
       "{n} match": { "one": "{n} совпадение", "few": "{n} совпадения", "many": "{n} совпадений" }
     },
     "obsolete": {}
   }
   ```

   - ключ — английский текст, с контекстом — `текст|контекст`;
   - пустой перевод `""` — еще не переведено, показывается английский;
   - множественное число — категории CLDR (`one`, `few`, `many`, `other`), ключ — форма
     единственного числа; правила категорий — своя таблица по языку (в рантайме Sciter нет
     `Intl.PluralRules`), для неизвестного языка — как в английском;
   - `obsolete` — строки, пропавшие из кода: перевод не теряется, если английский текст
     только поправили.
4. **Имена файлов — теги BCP 47**, самые короткие, что еще описывают отличие текста: `ru`,
   `pt-BR`, `zh-Hans`. Язык пользователя (`ru-KZ`) ищется отрезанием частей справа
   (`ru-KZ` → `ru`), затем — любой перевод того же языка, затем английский.
5. **Извлекатель строк** (`scripts/i18n-extract`, как `lupdate`): собирает `tr`/`trc`/`trn`
   из `resources/` и `source/`, добавляет новые строки в каталоги пустыми, пропавшие уносит
   в `obsolete`, сортирует ключи (читаемый diff). Тесты `tests/js` проверяют, что каталоги
   полны и параметры переводов совпадают с оригиналом.
6. **Псевдолокаль** для проверки: `Open File...` → `[Ôþéñ Fîļé... ~~~]` — все, что на экране
   осталось обычным английским, не обернуто в `tr`; удлинение показывает, где текст
   обрежется (русский длиннее английского примерно на треть).
7. **Смена языка на лету**:
   - элемент помнит исходник (`data-tr`, параметры), смена языка — один проход по документу;
   - меню пересобирается из `appMenu`; системные пункты macOS (Services, ...) не трогаем;
   - системные диалоги macOS (`NSOpenPanel`) берут язык при запуске: другой язык они
     покажут после перезапуска (`AppleLanguages`, `ru.lproj` в бандле).
8. **Ошибки бэкенда** приходят в скрипт кодом с параметрами, переводит их скрипт; тексты
   ошибок ОС вставляются параметром как есть.
9. **Сочетания клавиш** не переводятся (`⌘⇧S`, `Ctrl+Shift+S`). Мнемоники переводятся вместе
   с подписью (`&Файл`), меню-бар должен узнавать их по физической клавише.
10. **Пользовательские переводы** — позже: папка `translations/` в данных пользователя (не в
    бандле: подписанный `.app` менять нельзя), файл там добавляет язык или перекрывает
    встроенный. Список языков строится по найденным файлам (`locale`, `name` внутри).

## Этапы

Выбор языка в Settings (Appearance → Language) сделан сразу после ядра, раньше этапов 2–5,
чтобы проверять переводы по ходу работы: «System» (язык системы, `env.language()` и
`env.country()`), English, языки найденных каталогов (бэкенд: `getLanguages`,
`getTranslation(locale)` с выбором по цепочке тегов, `ui/translations`), Pseudo. Настройка
сохраняется в `settings.json` (`language`, "" — язык системы). Перерисовка на лету — на этапе 5:
пока новый язык видят только тексты, построенные после выбора.

1. Ядро: `tr`/`trc`/`trn`, правила множественного числа (en, ru), подстановка параметров,
   псевдолокаль; извлекатель и тесты каталогов.
2. D: каталоги читает бэкенд (поиск файлов, выбор языка), меню переводится и пересобирается.
   - `backend.useLanguage(locale)`: бэкенд берет каталог языка (`ui/translations.Catalog`,
     псевдолокаль — свой `pseudoize`, как в JS), меняет подписи нативного меню macOS и отдает
     каталог скрипту; скрипт перерисовывает меню-бар Windows/Linux.
   - `appMenu(platform, tr)`: метки пишутся как `tr("&File")`, где `tr` — переводчик-параметр;
     модель меню остается чистой функцией, а извлекатель находит тексты.
   - Мнемоника берется из перевода (`&Файл`); кириллическая буква узнается по клавише русской
     раскладки (ЙЦУКЕН), какая бы раскладка ни была включена: Alt+Ф — это KeyA.
   - Нативное меню macOS строится один раз; другой язык только меняет подписи созданных
     пунктов (`setTitle:`). Пересборка удаляла бы пункт, чье действие еще идет (Settings…,
     открытые из меню), и могла уронить приложение; системные пункты не трогаем.
   - Тест D проверяет мнемоники меню в каждом каталоге (есть и не повторяются в меню),
     проверка каталогов — что перевод не потерял и не добавил мнемонику (`&` перед буквой).
3. Перевод строк JS/HTML по модулям, даты в недавних файлах.
   - То, что строится один раз (разметка `.htm`, JSX-скелет панели), помечается исходником в
     атрибуте: `<header data-tr="Filters" />`, `data-tr-title`, `data-tr-placeholder`;
     `i18n/dom.translateTree(root)` переводит помеченное при создании и при смене языка.
     Извлекатель берет эти тексты из разметки и JSX.
   - То, что рисуется заново, зовет `tr()` само; при смене языка `script.js` рисует заново
     заглушку, вкладки, меню-бар и зовет `languageChanged()` каждой панели.
   - Фраза с элементами внутри — одна строка: `trParts("{open} a log with {shortcut}",
     { open: <button/>, shortcut: <kbd/> })`, порядок частей — как в переводе.
   - 3а: окно (заглушка, недавние файлы и их время, вкладка New Tab, Copy Row); 3б: панель
     документа и поиск; 3в: настройки и редактор правил.
4. Ошибки бэкенда — коды с параметрами.
5. Язык в Settings, смена на лету, локализация бандла macOS.
