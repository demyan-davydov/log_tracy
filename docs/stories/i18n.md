# Интернационализация

Ветка: `i18n`.

Все, что пользователь видит в интерфейсе, должно переводиться. Сначала английский (исходный)
и русский. Содержимое логов, заголовки колонок форматов, уровни (Fatal, Error, Warn, ...) и
текст сочетаний клавиш не переводятся.

## Решения

1. **Подход как в Qt / gettext**: в коде пишется английский текст, он же ключ перевода и
   запасной вариант, если перевода нет:
   - `tr("Open File...")`, с параметрами `tr("Found {count}", { count })`;
   - контекст для омонимов: `trc("noun", "Filter")`;
   - множественное число: `trn("{n} match", "{n} matches", n)`.

   Аргумент — всегда строковый литерал: иначе строку не найти автоматически.
2. **Встроенный механизм Sciter (`@"text"`, хуки `JSX_translateText`) не используем**: это
   нестандартный синтаксис, модули с ним не загрузятся в `node --test`.
3. **Каталоги — JSON** (без своих парсеров и зависимостей), по файлу на язык:
   `resources/i18n/translations/<тег>.json`. Код слоя переводов лежит в `resources/i18n/`.

   ```json
   {
     "locale": "ru",
     "name": "Русский",
     "messages": {
       "&Open File...": "&Открыть файл...",
       "Filter|noun": "Фильтр",
       "{n} match": { "one": "{n} совпадение", "few": "{n} совпадения", "many": "{n} совпадений" }
     },
     "obsolete": {}
   }
   ```

   - ключ — английский текст, с контекстом — `текст|контекст`;
   - пустой перевод `""` — еще не переведено, показывается английский;
   - множественное число — категории CLDR (`one`, `few`, `many`, `other`), ключ — форма
     единственного числа; правила категорий — своя таблица по языку (в рантайме Sciter нет
     `Intl.PluralRules`), для неизвестного языка — как в английском;
   - `obsolete` — строки, пропавшие из кода: перевод не теряется, если английский текст
     только поправили.
4. **Имена файлов — теги BCP 47**, самые короткие, что еще описывают отличие текста: `ru`,
   `pt-BR`, `zh-Hans`. Язык пользователя (`ru-KZ`) ищется отрезанием частей справа
   (`ru-KZ` → `ru`), затем — любой перевод того же языка, затем английский.
5. **Извлекатель строк** (`scripts/i18n-extract`, как `lupdate`): собирает `tr`/`trc`/`trn`
   из `resources/` и `source/`, добавляет новые строки в каталоги пустыми, пропавшие уносит
   в `obsolete`, сортирует ключи (читаемый diff). Тесты `tests/js` проверяют, что каталоги
   полны и параметры переводов совпадают с оригиналом.
6. **Псевдолокаль** для проверки: `Open File...` → `[Ôþéñ Fîļé... ~~~]` — все, что на экране
   осталось обычным английским, не обернуто в `tr`; удлинение показывает, где текст
   обрежется (русский длиннее английского примерно на треть).
7. **Смена языка на лету**:
   - элемент помнит исходник (`data-tr`, параметры), смена языка — один проход по документу;
   - меню пересобирается из `appMenu`; системные пункты macOS (Services, ...) не трогаем;
   - системные диалоги macOS (`NSOpenPanel`) — на языке системы, если бандл его объявляет
     (`ru.lproj`); на язык, выбранный в Settings, их не переводим.
8. **Ошибки бэкенда** приходят в скрипт кодом с параметрами, переводит их скрипт; тексты
   ошибок ОС вставляются параметром как есть.
9. **Сочетания клавиш** не переводятся (`⌘⇧S`, `Ctrl+Shift+S`). Мнемоники переводятся вместе
   с подписью (`&Файл`), меню-бар должен узнавать их по физической клавише.
10. **Пользовательские переводы** — позже: папка `translations/` в данных пользователя (не в
    бандле: подписанный `.app` менять нельзя), файл там добавляет язык или перекрывает
    встроенный. Список языков строится по найденным файлам (`locale`, `name` внутри).

## Этапы

Выбор языка в Settings (Appearance → Language) сделан сразу после ядра, раньше этапов 2–5,
чтобы проверять переводы по ходу работы: «System» (язык системы, `env.language()` и
`env.country()`), English, языки найденных каталогов (бэкенд: `getLanguages`,
`getTranslation(locale)` с выбором по цепочке тегов, `ui/translations`), Pseudo. Настройка
сохраняется в `settings.json` (`language`, "" — язык системы). Перерисовка на лету — на этапе 5:
пока новый язык видят только тексты, построенные после выбора.

1. Ядро: `tr`/`trc`/`trn`, правила множественного числа (en, ru), подстановка параметров,
   псевдолокаль; извлекатель и тесты каталогов.
2. D: каталоги читает бэкенд (поиск файлов, выбор языка), меню переводится и пересобирается.
   - `backend.useLanguage(locale)`: бэкенд берет каталог языка (`ui/translations.Catalog`;
     при псевдолокали — никакого: псевдотекст делает только скрипт, тексты бэкенда остаются
     английскими), меняет подписи нативного меню macOS и отдает каталог скрипту; скрипт
     перерисовывает меню-бар Windows/Linux.
   - `appMenu(platform, tr)`: метки пишутся как `tr("&File")`, где `tr` — переводчик-параметр;
     модель меню остается чистой функцией, а извлекатель находит тексты.
   - Мнемоника берется из перевода (`&Файл`); кириллическая буква узнается по клавише русской
     раскладки (ЙЦУКЕН), какая бы раскладка ни была включена: Alt+Ф — это KeyA.
   - Нативное меню macOS строится один раз; другой язык только меняет подписи созданных
     пунктов (`setTitle:`). Пересборка удаляла бы пункт, чье действие еще идет (Settings…,
     открытые из меню), и могла уронить приложение; системные пункты не трогаем.
   - Тест D проверяет мнемоники меню в каждом каталоге (есть и не повторяются в меню),
     проверка каталогов — что перевод не потерял и не добавил мнемонику (`&` перед буквой).
3. Перевод строк JS/HTML по модулям, даты в недавних файлах.
   - То, что строится один раз (разметка `.htm`, JSX-скелет панели), помечается исходником в
     атрибуте: `<header data-tr="Filters" />`, `data-tr-title`, `data-tr-placeholder`;
     `i18n/dom.translateTree(root)` переводит помеченное при создании и при смене языка.
     Извлекатель берет эти тексты из разметки и JSX.
   - То, что рисуется заново, зовет `tr()` само; при смене языка `script.js` рисует заново
     заглушку, вкладки, меню-бар и зовет `languageChanged()` каждой панели.
   - Фраза с элементами внутри — одна строка: `trParts("{open} a log with {shortcut}",
     { open: <button/>, shortcut: <kbd/> })`, порядок частей — как в переводе.
   - 3а: окно (заглушка, недавние файлы и их время, вкладка New Tab, Copy Row); 3б: панель
     документа и поиск; 3в: настройки и редактор правил.
   - Фильтр файлового диалога собирает `file-types.fileFilter`: переводится имя типа, шаблоны
     (`*.dlt;*.log`) остаются как есть.
   - Панель документа при смене языка перерисовывает фильтры, редактор поиска и показанные
     статусы, таблицы не трогает; скрытая панель делает это при показе (`textsStale`).
   - Диалоги — свои страницы со своим экземпляром `i18n.js`: им передается каталог
     (`currentCatalog()` → параметр `catalog`, `setCatalog` в диалоге). Подпись рядом с
     чекбоксом — отдельный `<span data-tr>`: пометка на `<label>` стерла бы чекбокс.
   - Имена новых наборов и правил («New Filter», «New Rule») дает бэкенд — это этап 4.
4. Тексты бэкенда для пользователя (ошибки) переводит сам бэкенд, на границе с интерфейсом.
   - Решили переводить в бэкенде, а не в скрипте: шаблон с параметрами нужен в любом случае
     (ошибки рождаются в нижних слоях и на потоке индексации, где каталога нет), а перевод в
     `AppSession` не меняет скрипт — он как получал строки, так и получает. Цена: уже
     показанная ошибка не переводится на лету, до следующего раза.
   - `utils/ui_text`: `UiText` — английский шаблон с параметрами (параметр — свой `UiText` или
     строка как есть), `UiTextException` его несет, `msg` — его английский (для лога и тестов).
     `uiText("no column \"{column}\" in this log", "column", id)` — литерал, извлекатель
     находит его в D (кроме блоков `unittest`).
   - `Catalog.translate(UiText)` переводит шаблоны, вложенные тексты так же, строки как есть.
   - Тексты ОС и библиотек (errno, `std.regex`) не переводятся — встают параметром или
     приходят как есть: ошибку открытия файла отображение в память дает словами системы
     («Can't open <path> (No such file or directory)»), стартовый экран показывает причину в
     скобках (`failureReason`).
   - Ошибка операции идет с потока индексации шаблоном (`OperationFinished.error` — `UiText`,
     его массивы неизменяемы, так что он копируется и из `const`), машины видов хранят его, а
     `toJson` вида ставит текст функцией сессии (`textForUser`, перевод по каталогу).
   - 4а: открытие и повтор файла, статусы, индексы, форматы; 4б: фильтры и редактор правил,
     имена новых наборов и правил; 4в: остальное.
   - Фильтры: `ruleError`, `conditionErrors` и заметки `.dlf`
     (`fromDlf`, `toDlf`) — `UiText`. команды `DocumentFilters` возвращают `UiText`, их
     переводит сессия (`filterCommand`), как остальные ошибки; то, что он делает текстом сам
     (JSON панели с причиной «не применяется», имя нового набора), получает функцию перевода
     параметром (`TextForUser`, по умолчанию английский), как `toJson` машин видов. Имена «New Filter» и «New Rule» — данные пользователя: переводятся один раз,
     когда набор или правило создается.
   - Не переводятся служебные тексты, которых пользователь не видит: разбор JSON поиска от
     скрипта, вариант syslog из настроек, установка обработчиков сигналов при старте.
5. Язык в Settings, смена на лету, локализация бандла macOS.
   - Pseudo в списке языков — только при `DLT_PSEUDO_LOCALE=1` (как `DLT_MENU_BAR`): бэкенд
     добавляет его в `languagesJson`, скрипт показывает пункт, только если он есть.
   - macOS: `scripts/bundle_mac.sh` объявляет языки бандла (`CFBundleLocalizations`, по
     `<тег>.lproj` на английский и каждый каталог) — иначе системные диалоги остаются
     английскими. Они идут на языке системы: при «Системном» (почти всегда) он совпадает с
     интерфейсом.
   - Проход с Pseudo: непереведенного не осталось; английскими остаются заголовки колонок,
     данные журнала и уровни — так и решено. Русский и Pseudo длиннее английского: «Загрузить
     фильтр» не помещается рядом с «Новый фильтр» в узкой боковой панели — вёрстку не трогали,
     решает пользователь.

## Упрощение (ветка `i18n-simplify`)

Ревью ветки на простоту: часть кода решала редкие случаи ценой целых механизмов.

- Убрана запись `AppleLanguages` приложения (системные диалоги на языке, выбранном в
  Settings, со следующего запуска). Ради редкого случая — язык не системный — она тянула
  Objective-C (`ui/system_language`), отдельный вызов `getSystemLanguage` и чтение языка
  системы из глобального домена: свой `AppleLanguages` подменял язык системы для самого
  приложения, «Системный» переставал быть системным. Теперь диалоги на языке системы.
- Псевдолокаль только в скрипте: в D был свой `pseudoize`, сверенный с JS до единиц UTF-16,
  ради псевдотекста в меню и ошибках бэкенда. Теперь они при Pseudo английские.
- Панель при смене языка не хранит и не перерисовывает ошибки бэкенда (поиска, повтора
  потерянного файла): бэкенд переводит их, когда присылает, и перерисовка давала смесь
  языков («Still unavailable: файла нет»). Ошибка остается на своем языке до следующей.
- Месяцы недавних файлов — массив `trc(...)` в вызове, без массива функций.
- `DocumentFilters` не хранит переводчик (он был протянут через `DocumentUi` ради старых
  тестов): команды возвращают `UiText`, переводит сессия; JSON и имена получают функцию
  перевода при вызове. Один способ для всех текстов бэкенда.
- Причина «не применяется» больше не поле `FilterRule.problem`: это было состояние времени
  работы внутри данных, которые сохраняются в настройки файла, и `UiText` из-за него
  попадал в хэш `AppSettings` (самописный `toHash`). Теперь `DocumentFilters` держит причины
  по `RuleId` (`problemOf`), находит их, когда правило приходит или меняется; `toHash` убран.
  Поле обещало и причину от импортера («то, что модель не выражает»), но ни один импортер ее
  не ставил.
- Ошибки ОС при открытии файла снова словами системы: частые коды (`ENOENT`, `EACCES`,
  `ERROR_ACCESS_DENIED`, ...) больше не заменяются нашими фразами («файла нет», «нет прав»).
  Фраза по коду не всегда верна (`ERROR_ACCESS_DENIED` приходит и для папки), а по тексту ОС
  причину легко найти; переводить ошибки ОС мы и так не собирались. `mapped_file` — как в
  `master`, стартовый экран снова берет причину из скобок (`failureReason`).
