# Файлы интерфейса внутри программы

Ветка: `embed-resources`.

Раньше окно читало HTML, CSS и JS из папки `resources/` на диске: `app.d` перебирал пять мест,
где мог лежать `main.htm` (рядом с программой, `../Resources` бандла macOS, текущая папка), а
bundle-скрипты копировали всю папку в дистрибутив. Каталоги переводов тоже читались с диска.
Хотелось, чтобы программа была одним файлом (плюс библиотека Sciter) и не зависела от того,
откуда ее запустили.

## Решение

- Файлы `resources/` встраиваются в программу string import'ом D (`stringImportPaths
  "resources"` в `dub.sdl`): таблица `ui/app_resources`, `switch` по пути со `static foreach`
  по списку файлов.
- D не умеет перечислить папку при компиляции, поэтому список файлов написан руками. Unittest
  сверяет его с папкой на диске: забытый (или удаленный) файл роняет `dub test` и называет
  себя. Иконки (`app.icns`, `app.ico`, `app.png`) и `app.rc` интерфейсу не нужны и не
  встраиваются: их берут bundle-скрипты и ресурсный скрипт Windows.
- Окно отдает файлы Sciter по адресу `this://app/<путь>`: `SciterWindow` ставит host callback
  и на `SC_LOAD_DATA` спрашивает `onLoadData(uri)`, `MainWindow` отвечает из таблицы.
  `main.htm` грузится через `SciterLoadHtml` с базой `this://app/main.htm`, одинаково на всех
  платформах, так что обход падения `SciterLoadFile` на Linux больше не нужен.
- Относительные адреса (модули `./tabs.js`, `i18n/plural.js` из `i18n/i18n.js`, CSS,
  `showModal("settings.htm")`) Sciter разрешает от базы сам: скрипт не менялся. Диалоги
  получают обработчик главного окна, их файлы приходят туда же.
- Каталоги переводов — встроенные файлы `i18n/translations/*.json`: `ui/translations` берет
  каталоги как пары «имя файла → текст» (`CatalogFile`), а не как папку.

## Что пробовали

- Короткая схема `app:main.htm`. Не годится: от адреса без `//` и пути Sciter не разрешает
  относительные ссылки — `./i18n/i18n.js` пришел как `app:./i18n/i18n.js`, а `./plural.js`
  внутри него как `app:./plural.js`, без папки. `this://app/` — договоренность самого Sciter,
  с ней все разрешается правильно.
- В биндинге `SciterHostCallback` был объявлен без `extern (C)`, и функцию обработчика нельзя
  было передать в `SciterSetCallback`. Исправлено.

## Решили не делать

Подмену встроенных файлов файлами с диска (переменной окружения, для правки JS без
пересборки). Два источника одних и тех же файлов — путь к ошибкам, которые трудно отследить;
отладочная сборка быстрая. Правка HTML, CSS или JS теперь требует пересборки. Если это станет
мешать, вернемся к вопросу.
