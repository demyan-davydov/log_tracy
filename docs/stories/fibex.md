# FIBEX: декодирование non-verbose DLT

Ветка: `fibex`. Что такое FIBEX, как его обычно подключают и какие были варианты:
`docs/fibex.md`.

## Что решили

- **FIBEX у документа** (вариант 2 из `docs/fibex.md`): «Загрузить FIBEX…» для открытого
  DLT-файла на странице «О файле», рядом путь загруженного, «Выгрузить». Повторная загрузка
  другого файла заменяет текущий. Путь запоминается в записи списка недавних (как формат), и
  при следующем открытии файла FIBEX подхватывается. Сам FIBEX большой, поэтому хранится только
  путь.
- **Ключ поиска** — ID сообщения, а если в сообщении есть AppId и CtxId, то тройка (ID, AppId,
  CtxId); ECU в ключ не входит. В логе нескольких ECU с пересекающимися ID возможна путаница:
  известное ограничение, добавить ECU в ключ — небольшое изменение, если понадобится.
- **Кадр с уже встреченной тройкой** (ID, AppId, CtxId) пропускается, первый остаётся.
- **ARXML** не поддерживаем: в бэклоге.
- **FIBEX — часть формата документа.** Декодирует запись `DltFormat`, и все, кто читает записи
  (таблица, фильтр, поиск, MCP, копирование), получают расшифрованное сообщение без особых
  шагов. Разбор payload non-verbose сообщения — знание о DLT, ему место в `formats/dlt`.
- **Смена FIBEX не переиндексирует файл.** Границы записей от FIBEX не зависят: индекс смещений
  остаётся. Но FIBEX меняет AppId, CtxId, уровень и текст, по которым работают фильтр и поиск,
  поэтому их индексы пересчитываются, как при смене фильтра.

## Этапы

1. Парсер FIBEX: `formats/dlt/fibex` (переписан, см. ниже).
2. Декодирование non-verbose в `DltFormat`: строка выглядит как verbose.
3. FIBEX в формате документа, замена у открытого документа с пересчётом фильтра и поиска.
4. Вызовы бэкенда и UI на странице «О файле»: загрузить, выгрузить, путь.
5. Путь в записи недавних и подхват при открытии.

## Парсер

Старый `formats/dlt/fibex` нигде не использовался и разбирал XML эвристикой: сопоставлял ID
только с текстом. Переписан как разбор подмножества FIBEX, которое генерируют инструменты
DLT, потоком событий `dxml` (файл бывает в десятки мегабайт, дерево целиком не нужно):

- `FRAME` с `ID="ID_<десятичный Message ID>"` — сообщение; из его `MANUFACTURER-EXTENSION`
  берутся `MESSAGE_TYPE`, `MESSAGE_INFO` (уровень), `APPLICATION_ID`, `CONTEXT_ID`,
  `MESSAGE_SOURCE_FILE`, `MESSAGE_LINE_NUMBER`; `PDU-REF` по порядку — части сообщения;
- `PDU`: с `DESC` — статический текст, иначе значение: тип по имени сигнала `SIGNAL-REF`
  (`S_UINT16`, `S_FLOA32`, `S_STRG_ASCII`, …), длина — `BYTE-LENGTH` PDU. Сигнал не
  разрешается через `SIGNALS` и `CODINGS`: инструменты, генерирующие FIBEX для DLT, пишут эти
  имена;
- строки и сырые данные в payload — с 2-байтной длиной перед ними;
- PDU виден только из своего файла; кадры всех файлов (папки) ищутся вместе.

Тесты — на своих маленьких FIBEX типичной структуры. Сторонние примеры в репозиторий не
копируем.
