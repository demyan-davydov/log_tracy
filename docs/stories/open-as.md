# Открыть как

Ветка: `open-as`.

## Что

Формат лога можно выбрать рукой, если автоподбор не угадал или не справился.

- **Где.** Строка «Формат» на странице File Info (ссылка «Переоткрыть как ▾» со списком),
  контекстное меню вкладки («Переоткрыть как»), меню «⋮» файла в недавних («Открыть как»: файл
  не открыт). Список один: «Определить автоматически», затем форматы по их названиям, текущий
  жирным, тот, что выбрало бы автоопределение, с пометкой «автоопределён» справа
  (`.ai/rules/ux.md`, 51; `registry.detectedFormatId`, в `documentInfo` и списке недавних).
- **Что происходит.** Файл открывается заново в той же вкладке (как Retry), файл без документа — в
  новой. Фильтры остаются: правило по колонке, которой нет у нового формата, не применяется.
  Якоря сбрасываются: они нумеруют сообщения старых записей. Выбор запоминается для файла.
- **Отказ.** Три вида (`.ai/rules/ux.md`, 52): система не дала файл («Failed to open»), формат не
  распознан («Format not recognized»), выбранный формат не прочитал («Failed to open as DLT»).
  Вид нужен интерфейсу: при отказе системы «Открыть как» отключено. Он хранится при заметке в
  списке недавних до успешного открытия, в `settings.json` его нет, и неудачная попытка не
  заменяет формат, которым файл открывали в последний раз.

## Как устроено

- `log_core/log_format.FormatException` (`unrecognized`, `unreadable`) — причина «формат»;
  любое другое исключение — «система». `OpenResult.failureJson` несёт `kind` и, если формат
  выбран, `format` (его название).
- `formats/registry.choiceFor(id, path, data)`: вариант, который формат читает в данных (иначе
  первый), и кодировка UTF-16 для текстового формата.
- `LogDocument(path, choice, byHand)`: выбранный рукой формат создаётся без отката к автоподбору.
- `AppSession.reopenAs(docId, formatId)` (пустой id — определить заново), `openFile(path,
  formatId)`, `formatsJson()`; `documentInfo` отдаёт `formatId`, список недавних — `format.id`.
- Скрипт: `resources/open-as.js` (список), `failureNote` в `new-tab.js` (подписи отказов),
  `recent-file-menu.js` (когда пункт включён).

## Найдено при проверке в окне

- Переоткрытие в формате с другими колонками роняло приложение при отрисовке (`ArrayIndexError`
  в `ColumnSet.column`): раскладка колонок документа осталась от старого формата. Теперь
  `AppSession.reopen` при `FormatChange.records` говорит видам, что колонки изменились
  (`tellColumnsChanged`).
- Диалог открытия на macOS брал типы файлов за единственно допустимые расширения, «All Files»
  его не снимал (`.bin`, `.gz` не выбрать): теперь без фильтра (`file-types.logFileFilter`).
  Не проверено на Windows и Linux, там фильтр прежний.

- «Определить автоматически» из меню недавних открывал файл в запомненном формате: пустой
  `formatId` у `openFile` значил «как в прошлый раз». Теперь это два вызова: `openFile(path)` и
  `openFileAs(path, formatId)` (пустой id — определить заново), в скрипте `backend.openFile` и
  `backend.openFileAs`.
- Ссылки в строках текста (File Info, тулбар «Фильтры») были `<button>` со снятым видом, и у них
  не совпадали шрифт и базовая линия. Теперь `<span class="text-link">` с `behavior: button`
  (`.ai/rules/ux.md`, 53); как открывается список «Переоткрыть как», см. ниже (вызов `popup()`
  вручную отброшен).

- Ссылка «Переоткрыть как» — `<span type="menu">` с `behavior: button popup-menu`. Так у Sciter
  устроен `<button type="menu">` («⋮» в недавних): `popup-menu` открывает `<menu>` нажатием и
  закрывает следующим, свой код не нужен (первая версия с `popup()` и обработчиками на `mousedown`
  открывала список снова тем же нажатием). `type="menu"` на `span` сам ничего не включает, нужно
  поведение. Ячейка «Формат» обновляется на месте, чтобы владелец открытого списка не исчезал
  под ним. Формат на File Info — плашка (`--bg-tab-inactive`, без рамки: высоту строки не меняет).

## Потом

- Меню приложения «Файл → Открыть как…» (подменю форматов, потом диалог файла).
- Статус «в этом формате записей не найдено» с тем же выбором: документ с нулём строк сейчас
  выглядит пустым и без объяснения.
- Выбор кодировки и варианта (у вариантов нет имён для пользователя).
- Не проверено в окне: подменю в «⋮» и в меню вкладки, список на File Info, жирный текущий пункт.
