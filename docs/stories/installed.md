# Настройки установленной программы

## Что

Дистрибутив (`node scripts/build.mjs dist`) собирается отдельным типом сборки dub `dist`: это
release плюс `version (Installed)`. Такая программа хранит `settings.json` и `settings.lock` в
папке пользователя:

- macOS: `~/Library/Application Support/Log Tracy/`;
- Linux: `$XDG_CONFIG_HOME/log_tracy/`, по умолчанию `~/.config/log_tracy/`;
- Windows: `%APPDATA%\Log Tracy\`.

Все остальные сборки (debug, `--release`, unittest) по-прежнему держат настройки рядом с
программой. Папка создаётся при первом запуске (замок) и при первой записи настроек.

## Почему так

- Это шаг к инсталляторам (DMG, `.deb`). Установленная программа не может писать рядом с
  собой: `/Applications/LogTracy.app/Contents/MacOS` — запись внутрь бандла ломает его подпись,
  а запущенный из карантина бандл (App Translocation) вообще только для чтения; `/opt` и
  `Program Files` пользователю недоступны на запись.
- Решает переменная сборки, а не тип оптимизации. Привязка к release смешала бы две вещи:
  локальный `run.mjs --release` делил бы настройки с установленной копией, а release
  запускается в одной копии на `settings.json` — одновременно с установленной он бы не
  запустился. С отдельным `dist` любая сборка разработчика живёт как раньше.
- Тип сборки dub, а не флаг вручную: у `dist` своя папка `build/<platform>-<arch>-dist/`
  (`targetPath` по `$BUILD_TYPE`), он не перезаписывает обычный release и не путает кеш.
- Выбор папки — обычная функция `settingsDir(installed, exeDir, env)` в `ui/app_settings`:
  юнит-тесты собираются без `Installed` и проверяют обе ветки через параметр, а `version`
  только подставляет его значение.
- Без переменных окружения (`HOME`, `APPDATA`) установленная копия пишет рядом с собой:
  лучше так, чем относительный путь от текущей папки. Относительный `XDG_CONFIG_HOME`
  игнорируется, как требует спецификация XDG.

## Что отвергли

- «Есть `settings.json` рядом — пишем туда, иначе в папку пользователя»: в свежей сборке файла
  нет, программа уходит в папку пользователя и рядом с собой его уже никогда не создаст.
- Файл-маркер `portable` рядом с программой: лишняя подвижная часть (забыли скопировать —
  настройки молча уехали). Понадобится, если появится портативная версия.
- Ключ `--settings <путь>`: со сборкой `dist` скриптам (`screenshot.mjs`, `app.mjs`) он не
  нужен, они запускают обычные сборки.
