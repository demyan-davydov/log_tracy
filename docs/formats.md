# Log formats

Формат определяется по началу файла (детекторы в `source/formats/registry.d`). Если ни один формат не подходит, текст открывается как plain text, а бинарные данные не открываются.

Текстовые форматы читают UTF-8 и UTF-16 (little- и big-endian): с BOM, а без BOM — если как есть файл подходит формату хуже (или не подходит совсем), а нулевые байты стоят только на одной стороне 16-битных единиц (так выглядит ASCII в UTF-16). Строка делится по единице U+000A, а не по байту `0x0A`, поэтому символы вроде U+0A0A не разрывают строку. Кодировка запоминается вместе с форматом. Каждый формат задает свои колонки таблицы и поля быстрого фильтра.

Файл из списка недавних открывается в том формате, в котором его открывали в прошлый раз (формат, вариант и кодировка сохраняются в настройках), без повторного определения; формат определяется заново, только если он не сохранен или эта сборка не может его создать (неизвестный формат, неверный вариант). Рядом с файлом в списке показывается значок формата из трех букв, полное имя — в подсказке.

## Supported
- **DLT** (`DLT`, бинарный): протоколы версий 1 и 2 со storage header версий 1 и 2 (файлы DLT), в любом сочетании. В версии 2: ID любой длины, время сообщения (UTC или от старта ECU), кадры сегментированных сообщений показываются текстом, имя файла, теги и privacy level читаются, но не показываются; payload считается little-endian. Verbose-аргументы всех типов (с именем и единицей, fixed point, 128-битные целые в hex, float16, целые с кодировкой hex/bin; строка с пометкой ASCII, чьи байты — UTF-8, показывается как UTF-8, как в DLT Viewer: писатели помечают так и UTF-8, иначе — символ на байт); non-verbose — по FIBEX, загруженному на странице «О файле» (файл или папка `*.xml`, запоминается для лога): AppId, CtxId, тип, уровень и части сообщения как у verbose; без FIBEX или без описания сообщения — `[message ID]`, hex и ASCII данных; control-сообщения с именами сервисов и статусов, разбор get_log_info (приложения и контексты с уровнями, trace status и описаниями), get_software_version, connection_info, timezone, marker. ECU берется из стандартного заголовка, если он там есть, иначе из storage header. Запись со слишком большой длиной в стандартном заголовке заканчивается на следующем storage header'е внутри неё и не накрывает следующие записи. Сообщение, которое приложение разрезало на verbose-сообщения с одним строковым аргументом `1/n: `, `2/n: ` ... одного отправителя, со счётчиком подряд, — одна запись с текстом всех частей без номеров; сообщение без последних частей — с пометкой `[2 of 3 parts]` (`docs/stories/joined-parts.md`). Так же склеивается сообщение, которое приложение разрезало без всякой метки по пределу в 1024 или 1023 байта текста (буфер в 1024 с нулём в конце): кусок такой длины (или до 3 байт короче, чтобы не резать символ UTF-8) без перевода строки в конце продолжает следующая запись того же отправителя со счётчиком +1, того же уровня, не позже чем через 5 мс, начинающаяся с символа, который не влез в кусок; не больше 64 кусков; если последний склеенный кусок сам обрезан — с пометкой `[cut]` в конце (`docs/stories/cut-pieces.md`). Файлы, переданные в логе протоколом передачи файлов DLT (FLST, FLDA, FLFI, FLER), собираются в список при загрузке и сохраняются из пакетов, пришедших подряд с первого; строки этих сообщений остаются в таблице как есть, интерфейса для списка пока нет (`docs/stories/file-transfer.md`). Колонки Cnt (счётчик сообщения), sId (Session ID) и Msg (Message ID) скрыты, пока пользователь не включит их в настройках колонок.
- **Plain text** (`TXT`): запасной формат, запись = строка
- **Android logcat** (`ADB`): `threadtime` (с годом `-v year` и без), `brief`
- **Kernel log (dmesg)** (`KRN`): обычный вывод (время от загрузки), `<priority>` (`dmesg -r`, `/proc/kmsg`), `dmesg -x` (facility и level по имени), `dmesg -T` (время по часам), `/dev/kmsg` (`priority,seq,usec,flags;message` со строками словаря)
- **Syslog** (`SYS`): BSD / RFC 3164 и journalctl `short`/`short-precise`, ISO (rsyslog, journalctl `short-iso`, с поясом и без), RFC 5424 (MSGID, structured data); `<priority>` дает уровень
- **Web server access log** (`WEB`): Common Log Format и Combined (nginx по умолчанию); HTTP-статус показывается как есть, его класс (5xx/4xx) дает уровень и цвет ячейки
- **CAN trace, candump `-l`** (`CAN`, SocketCAN): CAN, 29-bit ID, Remote, CAN FD, error frames
- **CAN trace, Vector ASC** (`ASC`): шапка (`base hex|dec`, `date`, `timestamps`), CAN, Remote, CAN FD (с символьным именем и без), ErrorFrame, прочие события

## Planned
- **DLT**: DLT без storage header (по serial и TCP) для потоков; сборка сегментированных сообщений версии 2 из кадров (строка последнего кадра показывает собранное сообщение), через ту же склейку записей при индексации, что и пронумерованные части (`PartedFormat`, `docs/stories/joined-parts.md`)
- **Логи приложений** «время, уровень, сообщение» (log4j/logback, spdlog, Python logging, glog): встроенные шаблоны, сейчас открываются как plain text
- **Пользовательские форматы**: шаблон из настроек тем же движком, что и встроенные
- **JSON Lines**: колонки по ключам (время, уровень, сообщение по известным ключам)
- **Текстовый экспорт DLT**
- **Access log**: построение разбора из строки `log_format` (nginx) / `LogFormat` (Apache); логи ошибок Apache и nginx; W3C Extended (`#Fields:`, IIS)
- **QNX slog2info**
- **Расширения поддержанных форматов**: `dmesg -x -T`, `dmesg --time-format iso`; `candump -x`; даты ASC на других языках; LIN/FlexRay/Ethernet в ASC как отдельные типы
- **CAN**: бинарные BLF и MF4; декодирование сигналов через DBC
- **Кодировки**: однобайтные (cp1251, Latin-1); сейчас UTF-8 и UTF-16
- **Потоковые источники**: растущий файл (`tail -f`), затем COM-порт и TCP (запись потока на диск, время прихода для строк без времени)
- **Ручной выбор формата** («Открыть как…»), если определение ошиблось
